EM64T-capable VM, hitting the bug-trigger path.

Interpretation:
* This is exactly the failure vit9696 reported in issue #9. Tiger's 2007-vintage
  dyld doesn't understand LC_DYLD_INFO_ONLY (load command bit pattern 0x80000022).
* XNU's grade_binary on this EM64T-capable VM CPU grades the x86_64 slice higher
  than i386, so dyld is invoked on x86_64 — and dies before main() can run.
* The same shipped v2.5.3 ran fine on real Tiger 10.4.5 (separate file in this
  directory): 10.4.5 predates x86_64 userland, so XNU grades x86_64=0 and picks i386,
  avoiding the bug-trigger path entirely.

v2.5.3 release artifact, used as the control for the v2.5.4 fix validation.
