PVE-host QGA protocol end-to-end verification — Tiger 10.4.11 / Darwin 8.11.1
=============================================================================
Captured 2026-06-05 from the Proxmox VE 9.1.1 host driving the Tiger 10.4.11 VM
through the standard `qm agent` command-line tool. This exercises the FULL stack:
PVE QGA proxy → qga unix socket → QEMU isa-serial chardev → Tiger /dev/cu.serial1
→ our daemon (LaunchDaemon-started) → JSON response → reverse path.

A response on this path proves all of the following work end-to-end:

  1. v2.5.4's x86_64 slice loaded (issue #9 fix)
  2. lipo-thin install put a single-arch i386 binary at /usr/local/bin/mac-guest-agent
     (vit9696's suggested UX improvement)
  3. LaunchDaemon plist registered, daemon autostarted at boot
  4. Daemon opened /dev/cu.serial1 with O_NONBLOCK (Codex hardening #1)
  5. PVE's QGA proxy handshake succeeded
  6. Tiger BSD serial driver delivered both PVE's request bytes AND our
     response bytes (the very class of bug from issue #10)
  7. JSON command dispatch matched our 45-command registry
  8. Response wrapping (\xff delimiter + \n) decoded by PVE without error
