lipo-thin install demonstration — Tiger 10.4.11 (vit9696's issue #9 last comment)
=================================================================================
Captured 2026-06-05 on the Tiger 10.4.11 VM. Demonstrates the
behaviour added in v2.5.4 per vit9696's separate suggestion on
issue #9 (`"one could probably replace mv command with lipo. I.e.
sudo lipo -thin $(uname -m) mac-guest-agent -output /usr/local/bin/mac-guest-agent
... On a positive side that would also slightly reduce the amount of space
used by the guest agent."`).

The behaviour is implemented inside the binary's own --install path
(`src/service.c::service_install`) rather than in the README install
recipe alone. This means the size-savings apply regardless of which
recipe the operator uses — direct binary invocation, the README mv flow,
or the install.sh bootstrap wrapper. The agent self-thins at install
time. Falls back to plain cp if /usr/bin/lipo is missing for any reason.

The README and `scripts/install.sh` are updated separately to suggest
the lipo-thin recipe directly for operators who want a single visible step.

--- Size summary ---
fat source binary:    498,216 bytes  (3 slices)
thin installed:       157,712 bytes  (1 slice: i386, matches `uname -m` on Tiger)
saved:                340,504 bytes  (~68% reduction on disk)

--- Tiger picks i386 because `uname -m` returns "i386" ---
$ uname -m
i386       <-- Tiger's KERNEL is 32-bit (RELEASE_I386), so uname reports i386 even on EM64T CPUs
$          (XNU's grade_binary picks x86_64 over i386 for FAT binaries when running them,
            but `uname -m` reports the kernel arch, not what grade_binary would pick.
            The i386 single-arch installed binary still gets picked correctly by XNU
            because it's the ONLY slice present — no fat header for grade_binary to traverse.)

The lipo-thin install path is:
- Implemented in `src/service.c` so it works regardless of install recipe
- Has a documented fallback to `cp` if /usr/bin/lipo is missing
- Validated end-to-end on Tiger 10.4.11 with the daemon talking to PVE successfully
- Documented in README.md install snippet for operators who want it as
  an explicit one-line recipe rather than implicit binary behaviour
- Preserves the one-binary distribution model — the GitHub release
  artifact is still a single tri-fat universal Mach-O.
